## 前言

你是否遇到过这样的场景？

- 🖥️ 在家里搭了一个 **Minecraft 服务器**，想让朋友一起玩

这些场景的共同问题是：**你的设备在内网（局域网）里，没有公网 IP，外网根本访问不到。**

解决方案就是——**内网穿透**。而**樱花内网穿透（NatFrp）** 是国内最知名的免费内网穿透平台之一，操作简单、节点丰富、对新手极其友好。

本教程将手把手带你从零开始，完成樱花内网穿透的全部配置。

## 一、什么是内网穿透？

### 1.1 通俗理解

想象你住在一个小区里（内网），小区有门禁（NAT / 防火墙），外面的快递员（外网用户）进不来。**内网穿透** 就相当于在门禁处开了一个「代收点」（公网服务器），快递员把包裹送到代收点，代收点再转交给你。

```
外网用户 ──→ 樱花服务器（公网IP） ──→ 隧道 ──→ 你的电脑（内网）
```

### 1.2 技术原理

| 概念 | 说明 |
|------|------|
| **NAT** | 网络地址转换，将内网 IP 映射为公网 IP，导致外网无法主动访问内网设备 |
| **隧道（Tunnel）** | 你的电脑主动与樱花服务器建立一条持久连接，所有数据通过这条通道转发 |
| **端口映射** | 将你的本地端口（如 `25565`）映射到樱花服务器的一个公网端口上 |
| **节点** | 樱花部署在各地的服务器，选择离你近的节点延迟更低 |

### 1.3 樱花 vs 其他方案

| 方案 | 成本 | 速度 | 易用性 | 适用场景 |
|------|------|------|--------|----------|
| **樱花 NatFrp** | 免费 / 付费加速 | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 游戏开服、Web预览、日常使用 |
| frp（自建） | 需要云服务器 | ⭐⭐⭐⭐⭐ | ⭐⭐ | 技术用户、长期使用 |
| ngrok | 免费有限 / 付费 | ⭐⭐⭐ | ⭐⭐⭐⭐ | Webhook、临时预览 |
| Tailscale | 免费 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 设备互联、远程桌面 |

## 二、注册与准备

### 2.1 注册樱花账号

1. 打开樱花内网穿透官网：**[https://www.natfrp.com](https://www.natfrp.com)**
2. 点击右上角 **「注册」**
3. 填写用户名、邮箱、密码，完成注册
4. 前往邮箱查收验证邮件，点击链接激活账号
5. 登录后进入 **「用户中心」**

> 💡 **提示**：注册后会获得一定的免费流量，日常使用完全够用。如果需要更高带宽和更多隧道，可以考虑付费套餐。

### 2.2 下载客户端

登录后，在导航栏找到 **「软件下载」**，根据你的操作系统选择对应的客户端：

| 操作系统 | 客户端 | 说明 |
|----------|--------|------|
| **Windows** | SakuraFrp Launcher | 图形界面，推荐新手使用 |
| **macOS** | SakuraFrp Launcher | 同上 |
| **Linux** | 启动器 / 命令行版 | 支持 systemd 服务 |
| **Android** | 移动端 App | 手机上也能用 |
| **Docker** | Docker 镜像 | 适合服务器部署 |

下载完成后解压到任意目录即可，**无需安装**。

## 三、创建隧道（核心步骤）

隧道就是连接你本地服务和公网的「桥梁」。下面我们以几个常见场景为例。

### 3.1 场景一：Minecraft 服务器开服

这是樱花最热门的使用场景。假设你在本地 `25565` 端口开了一个 MC 服务器。

#### 步骤：

1. 登录 [NatFrp 控制台](https://www.natfrp.com)
2. 点击左侧 **「隧道管理」→「创建隧道」**
3. 填写以下信息：

| 配置项 | 填写内容 | 说明 |
|--------|----------|------|
| **隧道名称** | `我的MC服务器` | 随意取名，方便识别 |
| **本地地址** | `127.0.0.1` | 如果服务在本机 |
| **本地端口** | `25565` | MC 默认端口 |
| **协议类型** | `TCP` | MC 使用 TCP 协议 |
| **节点选择** | 选择离你最近的 | 延迟更低 |

4. 点击 **「创建」**，系统会分配一个 **公网地址**（形如 `xxx.natfrp.cloud:12345`）

#### 在 MC 客户端连接：

```
服务器地址：xxx.natfrp.cloud:12345
```

把这个地址发给朋友，他们就能直接连接了！🎉

### 3.2 场景二：本地 Web 网站预览

假设你用 `npm run dev` 在本地 `3000` 端口跑了一个前端项目。

#### 步骤：

1. 创建隧道时选择：

| 配置项 | 填写内容 |
|--------|----------|
| **本地端口** | `3000` |
| **协议类型** | `TCP`（或 `HTTP`） |

2. 如果选择 **HTTP** 协议，樱花会提供一个更友好的域名（如 `xxx.natfrp.io`），无需记忆端口号
3. 将链接分享给别人即可预览

> 💡 **进阶**：选择 HTTP 协议时，樱花还支持 **自定义域名** 和 **HTTPS 证书**，适合正式演示。

### 3.3 场景三：远程桌面 / SSH

想在外面远程控制家里的电脑？

| 配置项 | 填写内容 | 说明 |
|--------|----------|------|
| **本地地址** | `127.0.0.1` | — |
| **本地端口** | `3389`（RDP）/ `22`（SSH） | 根据你的远程方式选择 |
| **协议类型** | `TCP` | — |

连接时使用 `xxx.natfrp.cloud:分配的端口` 即可。

## 四、启动隧道

### 4.1 使用图形界面（推荐新手）

1. 打开 **SakuraFrp Launcher**
2. 使用你的樱花账号登录
3. 在隧道列表中找到刚创建的隧道
4. 点击 **「启动」** 按钮

启动成功后，你会看到类似这样的日志：

```
[INFO] 隧道已启动: 我的MC服务器
[INFO] 公网地址: xxx.natfrp.cloud:12345
[INFO] 本地地址: 127.0.0.1:25565
[INFO] 节点: 上海 BGP
```

### 4.2 使用命令行

对于 Linux 服务器或喜欢命令行的用户：

```bash
# 下载命令行版
wget -O frpc https://nya.globalslb.net/natfrp/client/frpc/$(uname -m)/frpc

# 赋予执行权限
chmod +x frpc

# 使用 Token 启动隧道（Token 在用户中心获取）
./frpc -s <你的Token> -i <隧道ID>
```

### 4.3 开机自启（Linux systemd）

创建 systemd 服务文件：

```ini
# /etc/systemd/system/sakura-frp.service
[Unit]
Description=Sakura FRP Client
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/frpc -s <你的Token> -i <隧道ID>
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

然后启用服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable sakura-frp
sudo systemctl start sakura-frp

# 查看状态
sudo systemctl status sakura-frp
```

## 六、高级配置

### 6.1 自定义域名（HTTP 隧道）

如果你有自己的域名，可以配置 CNAME 解析到樱花提供的域名：

```
# DNS 设置
CNAME 记录：你的域名 → xxx.natfrp.io
```

然后在隧道设置中绑定自定义域名即可。

### 6.2 多隧道同时运行

你可以在启动器中同时启动多条隧道，例如：

- 隧道 1：MC 服务器 → `25565`
- 隧道 2：Web 预览 → `3000`
- 隧道 3：SSH 远程 → `22`

### 6.3 密码保护

对于 HTTP 隧道，可以设置 **访问密码**，防止陌生人访问你的服务：

```
隧道设置 → HTTP 设置 → 启用密码保护 → 设置用户名和密码
```

## 七、常见问题排查

### Q1：隧道启动失败，提示「端口被占用」

```
[ERROR] 本地端口 25565 已被占用
```

**解决方案**：
- 检查本地是否已经有服务在使用该端口
- Windows：打开 CMD 执行 `netstat -ano | findstr :25565`
- Linux：执行 `lsof -i :25565`
- 修改本地服务的端口，或换一个端口创建隧道

### Q2：隧道显示在线，但外网无法访问

**排查步骤**：

1. ✅ 确认本地服务正在运行且可以访问
2. ✅ 确认本地地址填写正确（`127.0.0.1` 而不是 `0.0.0.0`）
3. ✅ 检查防火墙是否放行了相关端口
4. ✅ 尝试切换节点
5. ✅ MC 服务器检查 `server.properties` 中 `server-port` 是否匹配

### Q3：连接延迟很高 / 频繁断开

**优化建议**：

- 切换到离你更近的节点
- 避免使用高峰时段（晚间）
- 考虑升级付费套餐获得更好的线路
- 检查本地网络是否稳定

### Q4：免费流量用完了怎么办？

- 等待下月刷新（每月有免费额度）
- 通过签到获取额外流量
- 考虑购买付费套餐

## 八、安全注意事项

⚠️ **内网穿透会将你的本地服务暴露到公网，请务必注意安全：**

1. **不要暴露敏感服务** — 如数据库（MySQL 3306）、Redis 等，只暴露需要对外的服务
2. **设置强密码** — 对于 MC 服务器、SSH 等，务必设置复杂密码
3. **及时关闭不用的隧道** — 不用时停止隧道，减少攻击面
4. **使用 HTTPS** — Web 服务尽量配置 SSL 证书
5. **定期检查流量** — 防止被他人盗用

## 九、与其他工具配合使用

### 9.1 + Docker

在 Docker 容器中运行樱花客户端：

```dockerfile
FROM alpine:latest
RUN wget -O /frpc https://nya.globalslb.net/natfrp/client/frpc/$(uname -m)/frpc && chmod +x /frpc
CMD ["/frpc", "-s", "<Token>", "-i", "<隧道ID>"]
```

### 9.2 + 宝塔面板

如果你使用宝塔面板管理服务器，可以在 **「计划任务」** 中添加守护脚本，确保樱花客户端掉线后自动重连。

### 9.3 + VS Code Remote

通过樱花隧道 + VS Code Remote SSH，可以在任何地方远程编码：

```
VS Code → Remote-SSH → 连接 xxx.natfrp.cloud:<SSH端口>
```
